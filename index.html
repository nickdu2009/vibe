01 Definition

Vibe Coding · 重新定义

✕ 它不是

  • 把任务复制进 Chat，等一段代码出来
  • 「让 AI 写完，我再 review 一下」
  • 把规范、风格、约束放进 prompt 里反复念
  • 每个新会话都从「我们的项目是 …」重新解释
  • 用 AI 一次性生成完美代码

✓ 它是

  • 把项目记忆、决策、约定结构化沉淀
  • 把工程纪律编码成可复用的 Skill
  • 把 AI 的输出当 Proposal，让规则与门禁裁决
  • 跨会话、跨工具、跨 Agent 仍然续得上
  • 每一步都可观测、可回滚、可审计
核心命题：AI 单次写代码本来就快——Vibe Coding 是让这份「快」在多项目、长时间维度上仍然稳得住。
02 The Shift

从 Chat 到 Workflow 的转变

维度Chat 模式（V1）Workflow 模式（V2）
会话单位一问一答有目标、有 plan、有 verify 的任务
记忆仅当前 context window跨会话的知识库（Markdown + 索引）
纪律靠 prompt 反复提醒编码成 Skill，自动触发
错误处理错了再试 / 撤回Review Loop + 最小验证 + 可回滚 diff
多 Agent一个 Chat 干所有事声明式 delegate，Tier 1/2 协议
交接「我把上下文复制给你」Handoff candidate · State checkpoint
产物代码片段代码 + 测试 + 文档 + 决策记录

在 IDE 集成、MCP、Hooks、Skills 都已成熟的 2026，Workflow 模式已经从 Power-User 玩具变成团队协作的最小公约数。

04 Pillar · 01

① Context First — 别让 AI 重新认识项目

痛点

  • 每个新会话都从「我们用 Go + Echo + GORM …」开始
  • AI 改了一处，破坏了你两周前定的约定
  • 项目记忆只存在你脑子里 / Slack 里 / 上一个 PR description 里

解法

  • 把项目记忆结构化沉淀：架构 / 决策 / 约定 / 验收标准
  • 会话开始第一件事：worktrail context "current task"
  • 每个 Agent 平台（Cursor / Claude / Codex）都自动 inject 同一个 Context Pack

## Maintenance hints

Next: /worktrail-distill

05 Pillar · 02

② Skill-Driven Discipline — 把"该怎么做"编码进 Skill

Skill = 一个可被自动触发、有明确边界、能产出可观测痕迹的行为模块。

触发是显式的

每个 Skill 描述什么时候 use / NOT use，告别「prompt 里念叨」。

边界是收敛的

小任务不强行升级到重型 Skill，AGENTS.md 治理路由。

痕迹是可审计的

Skill 执行输出 [task-validation] / [output] / [validate] 等结构化块。

反直觉的设计选择：Skill 是有意降速的——用「看起来慢」换「误改率与回滚成本更低」。
这不是 productivity tool，是 quality gate。

07 Pillar · 04

④ Multi-Agent Parallelism — 不是越多越快

什么时候真值得并行

  • 3 个以上独立调研区域
  • 不同模块、不同假设可以无共享写入地探索
  • 读多写少，结果可由父 agent 综合

什么时候不该并行

  • 一次直接搜索/读文件就够用
  • 工作区域高度重叠
  • 父 agent 无法清晰综合输出

分级协议

Tier 1 只读探索

无需声明，每个子 Agent 有清晰问题与证据格式即可。

Tier 2 写能力

启动前必须输出：
[delegate: 2-4 | split:<dim> | risk:<low|med|high>]

最多 4 个 active subagent。冲突时按证据强度裁决，不按数量投票。
08 Pillar · 05

⑤ Handoff & State — 长会话的命脉

当一个任务跨越多次 compact、跨工具、甚至跨人时——记忆才是稀缺资源。

EVENT
sessionStart

Cursor / Claude / Codex hook 触发，自动加载 Context Pack。

EVENT
state update

长任务持续记录目标 / 决策 / 验证 / 下一步。

EVENT
preCompact

压缩前自动 checkpoint，防止上下文丢失。

EVENT
handoff

结束 / 切工具前，结构化交接：根因 · 改动 · 验证 · 未决问题。

EVENT
candidate

知识沉淀为 pending candidate，等待 review · promote。

Worktrail Hook 哲学：Hook 只能记录证据，永远不能直接修改正式知识。
这是 AI 时代的「写权限分离」——agent 提案，人类裁决。

Skill 触发率、token 效率、跨模型一致性都有

14 Practice · Rhythm

两个杠杆 · 「多线 Vibe」工作节奏

🤖

杠杆 1 · Agent 是更快的 producer

不是「AI 当助手、我写代码」——Agent 写具体代码大多数情况比我又快又好：仿写已有结构、补 boilerplate、写 table-driven 单测 / 集成测试 / migration。
我做它做不好的：业务规则、跨模块边界、否决「聪明兼容」。

🔀

杠杆 2 · Agent 干活 = 我切换信号

Agent 在 A 项目跑 plan / 测试 / build 的几分钟到几十分钟，我立刻切到 B 项目——把 LLM 等待时间变成另一个项目的进度。
同时 2–4 个项目，是 Vibe Coding 改变工作量级的真正方式。

📌

切换前提 · Handoff

多线能并行，靠的是 worktrail context / handoff + skill 自动加载 = 回到任何项目 3 分钟接住上下文。不是靠记忆。

📊

评估单位变了

不再是「这个项目用了几天」，而是「同一周内能在几个项目同时推进」——这是工作量级的杠杆，不是效率的杠杆。

「Agent 写代码比我快比我好；我做边界裁决。
它在干活时，我去另一个项目——这才是 Vibe Coding 改变的节奏。」

22 Lessons

真实踩坑 · 7 条带血的教训

Gotcha · 01

AI Merge 会丢方法

consumer-finance 真实 commit d4b75b5 fix: restore lost methods。AI 辅助 merge 必须人工 review。

Gotcha · 02

AI 爱给「聪明 fallback」

PromptSpeed 报表：AI 默认「优先 meta，失败回退 Premium」。一句「不回退 policy.Premium」改变了产品语义——边界要由我说，不是 AI 猜。

Gotcha · 03

"修 bug" ≠ "理解需求"

双邮件 bug，AI 想删 TH 配置；我说「配置中的邮件都要发送哦」——AI 第一反应是修代码，我得提醒它先确认业务规则。

Gotcha · 04

Skill 不是越多越好

14 个 Skill 已是上限，每个都付维护成本。"最多 4 个活跃" 是硬约束。

Gotcha · 05

Cursor 没有项目级 Rules

Codex/Claude 有完整 user/project 双层；Cursor 仅 User Rules，治理需手动复制。

Gotcha · 06

Makefile 里的 DSN 别提交

goto 项目 makefile 含 staging DSN——分享/截图前 redact 检查必做。

Gotcha · 07

「Plan 看起来完美」≠「Plan 可执行」

这是 plan-review-loop 单独存在的原因——AI 写的 Plan 必须用真实仓库校验，不能光读文字。

23 Quotes

方法论金句 · 9 句话讲完 Vibe Coding

01 · Skills 管纪律，Worktrail 管记忆 —— Vibe Coding 的左右脑。
02 · 不是让 Agent 更忙，而是让每一步可验证、可交接、可审查。
03 · 知识不进正式文档，先进 candidate 队列 —— AI 时代的 PR for Docs。
04 · AI 输出永远是 advisory，validator + review gate 才是权威。
05 · 小任务轻装备，大改动才升级 impact-analysis / multi-agent。
06 · Local-first、无 daemon —— 工程师信任的是文件系统，不是又一个 SaaS。
07 · 工程师的杠杆，是「其它不变 / 不回退 / 去掉兼容 / 都要发送」这种短句——比长 prompt 更有力。
08 · 诚实地说：Agent 写代码大多数时候比我又快又好。我做的是它做不好的——业务规则、跨模块边界、否决「聪明兼容」、多项目同时切换。
09 · Vibe Coding 的进阶形态 —— 不是只用 AI 写代码，而是把 AI Agent 嵌入产品，让运营/交付团队也能 Vibe 配置。
